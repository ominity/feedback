# Contributing Feedback

Thank you for taking the time to help improve Ominity.

This repository is intended for bug reports and product feature requests. You do not need to contribute code to participate.

## Before creating an issue

Please search the existing issues first. Your problem or idea may already have been reported.

If an existing issue describes the same problem or request, add relevant information there instead of creating a duplicate. Reactions can also help us understand demand.

## Reporting bugs

When reporting a bug, try to provide enough information for us to reproduce it.

Useful information includes:

- A clear description of what went wrong
- Steps that consistently reproduce the problem
- What you expected to happen
- Which part of Ominity is affected
- Screenshots or screen recordings when relevant
- Browser and device information when relevant

Please keep each issue focused on a single problem. Separate unrelated bugs into separate reports.

## Requesting features

Feature requests are most useful when they explain the underlying problem rather than only prescribing a specific implementation.

Please describe:

- What you are trying to accomplish
- Why the current behavior makes this difficult
- What outcome you would like
- Any workaround you currently use

This context helps us understand whether there are other solutions that could address the same need more effectively.

## Public information and privacy

Issues in this repository are public.

Do not post passwords, API keys, access tokens, authentication credentials, customer information, personal data, payment information, or other confidential information.

If we need private information to investigate an issue, we will arrange an appropriate way to receive it.

## Issue lifecycle

The Ominity team may update, categorize, request additional information for, close, or mark issues as duplicates.

Feature requests are considered alongside product direction, user impact, demand, complexity, and available resources. An open or accepted request should not be interpreted as a commitment to a particular implementation or release date.
